# AMTI Optima recovery and verification

## Outcome

Work was performed in the Music checkout on main. The active desktop engine was repaired, and five original force-bearing October exports were processed on copies. In each trial there is one measured contact on one plate, eight marker-derived events and a complete strike–toe-off–strike interval for each side. The cycle CSV contains event-derived timing measurements. Joint kinetics and the final clinical GCD export did not pass the calibration prerequisite.

The acquisition project still contains only the generic plate. An offline reference configuration and a QTM RT location payload were reconstructed. There was no connected Optima available for QTM to define and calibrate. Applying a location to the current generic entry would attach geometry to the wrong device. Neither the internal device identifiers in a capture nor a type-2 C3D calibration placeholder supply a factory calibration. The cause of the missing saved definition is identifiable; the action or person that removed it is unknown.

## Event and force processing

1. October recordings have no stored timeline events. Their original C3Ds contained no gait events despite six valid force/moment channels. A force-bearing QTM export alone does not establish a labeled timeline. The current project configuration cannot explain the absence of events already demonstrated in those older recordings. In November Dynamic 4, the native Measurement/Events stream contains LSTRIKE at 1.658333 s (frame 200) and ROFF at 1.783333 s (frame 215). The other four dynamic November timelines are empty.
2. The desktop application invokes the engine under Gait-lab-Vicon-to-QTM. The Dynamic Analysis page enables auto-detection by default. The labeler uses heel and toe displacement relative to the pelvis, using the midpoint of valid posterior superior iliac spine markers when required. Vertical force identifies the region around plate activity. It does not independently measure bilateral strikes away from the plate.
3. The original alias lookup used substring matches. Anatomical marker names containing a short alias could supply the opposite foot, and both sides could be assigned the same heel. The new lookup respects ordered full marker aliases. Missing or invalid samples and filter edge peaks are excluded. The old minimum-count and synthetic toe-off/terminal-strike branches could produce unsupported events; those branches are no longer used by detection. A deliberately cleared timeline, an existing manual C3D and the matching open QTM gait timeline have priority.
4. EVENT:USED, event labels, available contexts and minute/second fields are read at import. RON/LON map to RSTRIKE/LSTRIKE. ROFF/LOFF retain their sides. A C3D point sample at index zero corresponds to the recording's first displayed frame. For these recordings frame = 1 + round(seconds × 120). A cropped-file test crosses the one-minute boundary and checks C3D → store → model frames. No one-frame timing shift was reproduced.
5. Event revisions are committed in session-local SQLite; JSON and C3D are projections. Concurrent creation of a fresh SQLite database actually failed in one of five original workers at PRAGMA journal_mode=WAL. The fix rechecks journal mode and retries a transient lock before starting a transaction. Sequential and five-process outputs match on all five trials. This result concerns event processing, not parallel end-to-end inverse dynamics.
6. The old force reader paired C3D platform order with numerically sorted active QTM series IDs for COP and sampling rate. With QTM disconnected it swapped/negated COP axes that ezc3d had already placed in the lab frame. For example, in October Dynamic 4 at analog index 2310, the reference COP was (201.38,219.01,0) mm; the previous fallback produced (219.01,−201.38,0). The repaired reader takes positions, frequency and wrench from the same C3D. Forces and moments use the subject-on-plate convention expected by DynamicMain. The loaded COP now agrees with an independent moment-over-force calculation. Old erroneous COP can change a joint's moment arm and hence joint power. The clinical magnitude has not been established.
7. The desktop page maps plate contact comments to FP0 on a side. All five original comments (left, right, right, right, left) agree with independent COP proximity and marker height at midstance. Side assignment has only been validated for these individual, single-plate contacts. The downstream solver requires calibrated segment/joint data and body mass. The actual static CLI stopped at missing BodyMass. The dynamic CLI stopped while opening the absent subject-specific static calibration. Zero measurements in previous reports cannot be attributed to one specific cause from these files.

## Trial results and outputs

trial-summary.csv gives before/after counts and force/marker timing differences; events.csv contains each label, frame, index, timestamp and source; gait-cycles.csv gives strike and off frames, stride duration and stance percentage. plots contains one plot per dynamic trial per session plus a five-trial overview. Vertical lines indicate marker events or preserved timeline events as labeled. Shading shows the single measured force contact. Off-plate events have marker evidence only.

The November folder has no C3Ds. Each matched derivative combines its own copied QTM and session.xml with the October export after comparing both stream inventories and each forceplate and measurement data-series stream byte for byte. Saved November events were transferred separately into those test derivatives. This produced two events for Dynamic 4 and eight for each other trial. The Dynamic 4 derivative was byte-identical before and after automatic labeling. Matching measurements give these tests traceability, not an independent repeat acquisition or a fresh November QTM export.
